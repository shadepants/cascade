## 🐛 Bugs & Issues Found (Code Review)

### 🔴 BUG 1 — Game Ends Immediately on First Jump (`App.tsx`)

**File:** `src/ui/App.tsx`, time-jump `useEffect`  
**Line:** `const MAX_YEARS = 150;`

The world is pre-simulated to `pregenYears: 500` (in `DEFAULT_CONFIG`). But `App.tsx` ends the run when `newWorld.currentYear >= MAX_YEARS` (150). Since `currentYear` starts at **500** after worldgen, the very first jump (which adds 10 years → year 510) always triggers the score screen immediately. The player never gets to explore across multiple eras.

**Fix:**
```ts
// App.tsx — either raise the ceiling or make it relative to world start
const MAX_YEARS = world.currentYear + 150; // relative cap
// or match it to pregenYears
const MAX_YEARS = state.world!.currentYear + 150;
```

### 🔴 BUG 2 — `resetEventIds()` Not Called Between Runs (`worldgen.ts` + `events.ts`)

**File:** `src/world/events.ts`  
`nextEventId` is a module-level counter. `resetEventIds()` is called in `generateWorld()` — but the **WebWorker** in `worker.ts` calls `runSimulation()` directly (not `generateWorld()`), so the event ID counter never resets between jump simulations. Event IDs bleed across runs (e.g. `evt_4203`), making causal chain lookups by `evt_NNN` reliable but the cascade scoring potentially double-counting events from prior runs after `Play Again`, since the counter keeps growing.

**Fix:** Call `resetEventIds()` at the start of each `runSimulation` (or inside the worker before the call), and also call it in the `RESET` reducer path in `store.ts`.

### 🔴 BUG 3 — Worker Returns Stale `world` Reference, Not a New Copy (`worker.ts`)

**File:** `src/simulation/worker.ts`
```ts
self.postMessage({ type: 'SIMULATION_COMPLETE', world, events: newEvents });
```
`runSimulation` **mutates** `world` in place (all phases do `world.factions[x].population = ...`, `world.events.push(...)`, etc.), so `newEvents` and `world` share overlapping data — `newEvents` is the events from this jump but `world.events` also already contains them (they were pushed inside `runSimulation`). In `App.tsx` the handler then does:

```ts
const cascadeEvents = newEvents.filter(e => e.playerCaused);
// ...then dispatches SET_WORLD with world (which already has those events pushed)
```

This means player-caused cascade events are **doubled** in `world.events` after a jump — once from `runSimulation`'s push, and the logic in App.tsx doesn't re-add them but the overlap means NPCs get duplicate knowledge entries. Also `newEvents` filtering in App.tsx implies they're separate, but they aren't.

**Fix:** Either have `runSimulation` return only the new events (don't push to `world.events` internally — return them and let the caller merge), or stop using `newEvents` in the worker return and filter by year from the mutated world.

### 🟡 BUG 4 — `applyStatDeltas` Population Clamped to 2000, But Faction Pop Can Reach 1000 (`tick.ts`)

**File:** `src/simulation/tick.ts`, `applyStatDeltas`  
Population is clamped to `Math.max(0, Math.min(2000, newVal))`, but the `FAMINE_POPULATION_MIN` threshold is 300 and the colonization trigger is `population > 600`. The starting range is 200–400 but there's no ceiling mismatch per se — however `DEFAULT_CONFIG` has `numFactions: 6` and the colonization NPC spawning doesn't push new NPCs into `world.settlements[newSettlement.id].npcs` — it pushes to `world.npcs` but the settlement `id` reference is from the `const id = ...` line which is correct. **Minor**, but worth noting.

### 🟡 BUG 5 — HUD Year/Position Text Clipped (Visual)

**Observed in-game.** The left side of the HUD bar is cut off — `Year XXXX` and `(x, y)` coordinates are partially hidden because the `.hud-left` div overflows or has no left padding. Confirmed from live screenshot: the label starts with `, 64)Act 0/6` — the `Year NNN (` prefix is cut.

### 🟡 BUG 6 — `drawGlyph` Off-Screen Check Missing Right/Bottom Bound for y-axis (`renderer.ts`)

**File:** `src/engine/renderer.ts`, `drawGlyph` function:
```ts
if (sx < -tileSize || sy < -tileSize) return;
if (sx >= camera.viewportWidth * tileSize) return;
// ⚠️ Missing: if (sy >= camera.viewportHeight * tileSize) return;
```
The bottom-edge cull for `sy` is absent. Entities below the viewport bottom will still have `fillText` called, wasting draw calls. Low impact (canvas clips it) but a correctness gap.

**Fix:**
```ts
if (sx >= camera.viewportWidth * tileSize) return;
if (sy >= camera.viewportHeight * tileSize) return;  // add this
```

### 🟡 BUG 8 — `pregenYears: 500` Makes World Start at Year 500; `storyteller` Debt Timers Are Year-Relative

**File:** `src/types.ts` / `src/simulation/storyteller.ts`  
`accumulateDebt` checks `entry.discoveredYear === currentYear` and `e.year > world.currentYear - 20`. Since `currentYear` starts at 500, all pre-history events are always older than 20 years at game start — no pre-history event can trigger narrative debt recovery. This means `yearsSincePlayerDiscovery` may never reset until the player takes an action post-jump, and the Storyteller interventions may fire prematurely. **Intended or not, worth double-checking.**

## 🎯 Sprite Coordinates (Your TODO)

The renderer uses **no sprite sheet / PNG at all** — it's fully ASCII/glyph-based canvas rendering using `fillText` with Unicode characters:

| Entity | Glyph | Color |
|--------|-------|-------|
| Player | `@` | `#ffcc00` |
| NPC | `N` | `#ddd` |
| Settlement | `■` | `#ffffff` |
| Item | `*` | `#aaffaa` |
| Ruin | `♜` | `#888888` |
| Resource iron | `i` | `#999` |
| Resource gold | `g` | `#facc15` |
| Resource relic | `†` | `#c084fc` |

There are **no PNGs loaded anywhere** in the codebase — no `<img>`, no `drawImage()`, no sprite atlas. The "eyeball PNGs in DevTools" TODO likely refers to inspecting the **biome tile colors** rendered on the canvas, which use hex fills from `BIOME_COLORS`. The coordinates being "off" in that context would mean the `drawGlyph` positioning — specifically the `sx + tileSize / 2` center-anchor for `textAlign: 'center'` and `sy + tileSize / 2` for `textBaseline: 'middle'`. These look mathematically correct, but at fractional `zoom` values (e.g. 0.7×), `tileSize` becomes a float and `Math.ceil(tileSize)` is only applied to `fillRect`, not to `fillText` positions — which can cause sub-pixel misalignment between tile fills and their glyphs at non-1.0 zoom.

**Fix for sub-pixel glyph drift at zoom ≠ 1.0:**
```ts
// In drawGlyph, round sx/sy to avoid sub-pixel drift
const rsx = Math.round(sx);
const rsy = Math.round(sy);
ctx.fillText(glyph, rsx + Math.round(tileSize / 2), rsy + Math.round(tileSize / 2) + yOffset);
```
